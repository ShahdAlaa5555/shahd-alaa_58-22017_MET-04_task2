I read 283 lines from bookings.jsonl, quarantined 24 and kept 259 bookings. The reasons were: 4 student ids in the wrong format, 4 totals not matching the tickets, 3 invalid ticket types, 3 quantities below 1, 3 bookings made on or after the event date, 3 duplicate booking_ids, 2 missing events and 2 empty ticket lists. I check duplicates after validation so that "first copy" means the first valid copy: if the first copy were broken, checking duplicates first would keep it, discard its correct re-send, and lose the booking. Swapping the order can change the counts in general, but on my file it gave the same result (3 duplicates, 259 left), because no re-sent booking had a broken copy. The field that drifted is promo_code. It first appears on a booking made at 2026-10-20 01:05 UTC and is in 193 documents, but one later booking lacks it, so it is optional. My models don't declare it, so Pydantic ignores it: bookings without it pass normally and nothing is quarantined because of it. total is not a column of fact_ticket_sales because the fact has one row per ticket entry, while total belongs to the whole booking. Copied onto every ticket row, SUM(total) would count each booking once per ticket entry in it, giving 42,000 EGP on my data instead of the true 31,285 EGP. The fact keeps amount instead, which adds up exactly to the bookings' totals.
